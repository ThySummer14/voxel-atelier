# 《机心》设计说明

> 一件实时体素作品：一枚**镂空陀飞轮腕表**，它不是摆拍模型——分针/时针读的是打开页面时的
> 真实系统时间，陀飞轮笼框 60 秒整一圈即秒针，摆轮 2.5 Hz 摆动，擒纵轮每一拍跳半齿。

## 1. 为什么选这个题材

工作区里前八件都是山水、岛礁、楼阁、江桥——同一套"东方大场景"语言。我要的不是再做一个更好看的
场景，而是**换一条别人没法比的轴**：

- **可证伪**。山水"像不像"是主观的；一枚表"走不走时"是可以用角度除以墙钟秒数算出来的。
  评分的人可以当场验证，不需要信任我的自述。
- **动的是机构，不是相机**。场景作品的动感来自环绕与染色；这枚作品的动感来自擒纵本身——
  每 0.2 秒一次的能量释放，是体素这种"硬边"语言少有的、真正适合表达的东西。
- **微缩静物 vs 大场景**。同一套体素语法，从"远看气势"换到"近看工艺"，
  倒角、鱼鳞纹、日内瓦条纹、蓝宝石玻璃、蓝钢螺丝——这些是前八件没有的词汇。

## 2. 体素规格

| 项 | 值 |
| --- | --- |
| 一格 | 0.2 mm（表壳直径 40 mm = 200 格） |
| 主网格 | 288 × 96 × 288（世界原点平移 (144, 0, 144)） |
| 实填格数 | 2,183,600 |
| 暴露格面 | 446,802 → 贪心合并后 164,600 三角 |
| 调色板 | 16 种材质 × 4 级明度 = 64 索引，Uint8 |
| 零件 | 37 件主网格零件 + 15 个游丝呼吸态小块 = 50 个网格 |
| 顶点缓冲 | 6.7 MB（位置 Int16 / 法线 Int8 / 三组颜色 Uint8 归一化） |

**为什么贪心合并必须按"零件 + 调色板索引"分组**：合并键是 `(partId << 8) | paletteIndex`，
跨零件不能合（否则旋转时面片会跟着错误的父级走），跨颜色不能合（否则手绘明度会被平均掉）。
代价是合并率只有 37%；换来的是每件零件可以独立旋转，且体素手绘感不丢。

**为什么光照烘焙进顶点色**：见 §5 第一条。

## 4. 传动表：全部由齿数比推出，不是填出来的周期

```
发条盒(96) → 中心小齿轮(12) → 中心轮(80)  1 周/小时  ← 带分针
中心轮(80) → 三轮小齿轮(8)  → 三轮(60)    1 周/6 分
三轮(60)   → 秒轮小齿轮(10) → 秒轮(60)    1 周/60 秒
秒轮(60)   → 擒纵小齿轮(6)  → 擒纵轮(15)  1 周/6 秒
笼框与秒轮同速：1 周/60 秒 = 秒针
```

三条必须同时成立的恒等式（`tools/accept-node.mjs` 逐条验）：

1. `centerRevSec == 3600`（中心轮带分针，锚点）
2. `fourthRevSec == 60`（由 60/8 × 60/10 推出，不是硬填）
3. `escapeRevSec == 齿数 × 2 / 拍频`——**轮系算出来的擒纵周期，必须等于瑞士杠杆
   "一次全摆推进一齿"要求的周期**。6s == 15×2/5 ✓ 这条闭合了，整张表才是自洽的。

摆频 2.5 Hz = 18'000 A/h，满条摆幅 295°，摆幅随动力按 `295·power^0.62 + 5` 衰减，
动力低于 1.5% 停走。上满需表冠转 22 圈。

## 5. 三处以上"别修回去"的设计决定

**(1) 光照烘焙进顶点色，浏览器与离线预览共用同一套 Lambert+AO 常数。**
不是偷懒，是为了让"我看到的"和"用户看到的"是同一张图。Node 端 DDA 光栅器
（`tools/lib-raster.mjs`）秒级出图，改几何不用开浏览器；浏览器端拿到的是同一套数值，
所以离线验收绿了，线上就不会翻车。实时只保留两项视角相关：菲涅尔冷光 + 极稀疏的鎏金星闪。

**(2) 不做 SSAO / Bloom / DOF 后期。**
金属小件最怕"糊"。这里用三个零风险的东西替代：CSS 暗角、CSS 暖光薄纱、CSS 胶片颗粒
（都是 `mix-blend-mode` 叠加，不进渲染管线），加上烘焙 AO 与接触阴影贴图。
放大镜是唯一真正的第二遍渲染（离屏 RT + 圆形遮罩 + 镜片失光 + 黄铜镜框）。

**(3) 器座是壶门透雕，不是实心台。**
光从拱洞里穿过去，在座面上留下体素台阶的影子。这是把"东方静物架"和"机械"缝在一起的那根线。
侧壁统一材质、只在顶面做漆纹——否则 170 万格的大漆会把贪心合并打碎成 20 万个矩形。

**(4) 游丝是 15 个独立体素态，逐帧切换，不是刚性旋转。**
真游丝会"呼吸"（内端随摆轮转、外端固定），刚性旋转是假的。这里把 `r = a0 + b·(θ+ψ)`
的 ψ 量化成 15 档，各自单独体素化成 46×6×46 的小网格，按摆轮角选档。
代价是多 15 个网格与 15 次小体量贪心合并（总共 <40ms），换来 2.5 Hz 下肉眼可见的呼吸。

**(5) 拆解视图带中文标注，且拆解时游丝只留一档。**
15 个半透明螺旋叠在一起会糊成一团白。

## 6. 与真实腕表的偏离（如实记）

| 偏离 | 原因 |
| --- | --- |
| 雕刻齿数（84/48/40/56）≠ 传动齿数（96/80/60/60） | 0.2mm/格的网格下，真实模数的齿会退化成 1 格锯齿。运动学一律按真实齿数表，视觉按"几齿并作一齿"雕刻 |
| 无匙机构简化为 表冠→小钢轮→大钢轮→过轮，棘轮与止逆爪单独摆在条轴上 | 真实布局里大钢轮在主夹板下方、棘轮在条盒夹板上方，同一小钢轮驱动；本作把它们都露在夹板之上供观赏 |
| 笼框外缘不做齿 | 真实笼框外缘也无齿；先前画了 96 齿，读起来像个齿轮，已删 |
| 游丝截面 1×2 格（0.2×0.4 mm） | 真实游丝厚 0.05 mm，在体素尺度下不可见，放大约 8 倍 |
| 摆轮只画 8 颗惯量螺钉，无宝石双盘式的全部细节 | 可读性优先 |
| 不做真实发条的力矩曲线，摆幅按 `power^0.62` 拟合 | 演示够用，且"条将尽→摆幅塌→停走"的行为正确 |
| 表镜是着色器圆盘，不是体素 | 体素玻璃在 0.2mm 尺度下只能是 1 格厚的板，反而不像玻璃 |

## 7. 踩过的坑（防止改回去）

- **`pose()` 的键名必须等于 `PARTS[].key`**。曾经 `pose` 返回 `cage/minute/escape`，
  而零件叫 `cageFrame/handMinute/escapeWheel`，于是**笼框、擒纵、指针全部静默不转**——
  画面看着正常，FPS 60，控制台零错误。现在 `accept-node` 逐条检查"声明了 spin 的零件
  在 pose 里有角度且随时间变化"，`accept-web` 再检查笼框 mesh 的 `rotation.y` 在渲染层真的变了。
- **时针漏算时区**。`displaySec` 是 UTC 纪元秒，分针/秒针不受整点偏移影响，只有时针差 8/12 圈。
  这条是**看图**看出来的（指针方向明显不对），数值断言当时全绿。现已补 `±0.03h` 反解断言。
- **`JX.pick()` 里二次 `localToWorld`**。three 的射线交点已是世界坐标，再乘一次矩阵会把
  零件位置整体偏移，一度让我以为"网格建错地方了"，白查十几分钟。
- **放大镜里必须关掉浮尘与表镜**。近景下加性光斑把画面冲成一片白。
- **`onBeforeCompile` 的教训沿用**：本项目不用它；着色器是自建 ShaderMaterial，
  自定义属性叫 `night`/`mat`，避开 three 内置的 `color`（只有 `vertexColors:true` 才声明）。
- **截图器必须每张回到基线状态**。曾经 `hack` 机位把停秒状态带进后面三张，
  `wound/drained` 全在停秒下拍，看着"动力 100% 却不动"。

| 操作 | 效果 |
| --- | --- |
| 在表冠上按住拖动 | 上链：棘轮声、大钢轮/过轮/棘轮/发条盒联动、动力与摆幅上升 |
| `1` / `0` 或点"停秒" | 拔出表冠 → 摆轮、擒纵、轮系全部冻住（真停秒）；`←`/`→` 拨针 |
