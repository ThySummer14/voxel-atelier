# 长风麦浪 · 体素作品

> 署名 **麦秋** · 2026
> AI 生成 · 模型 `new-provider/stealth/space-bunny-alpha`（运行时自报，我无法从内部验证底层基座）

黄昏逆光下的一片麦田山谷：一座石砌风车立在坡顶，农舍亮着灯，溪流从小桥下穿过，
小路从画面下缘一直引到农舍门口。麦子在风里起伏，云影缓慢掠过田野，
远处是几层被夕照染成蓝紫的山脊，太阳低低地挂在正前方偏左。

打开 `index.html` 即可（需要本地 http 服务，因为用了 ES module + import map）。

```bash
cd 长风麦浪
python3 -m http.server 8000
# 浏览器打开 http://127.0.0.1:8000/index.html
```

- 拖动环视、滚轮缩放、空格切换自动巡游
- `?cam=0..5` 切换预设机位，`?seed=整数` 换一片地形
- `?clay=1` 白模（只渲几何，用来核对构图）、`?shadows=0` 关阴影、`?t=秒` 定格动画

## 这张图是怎么做出来的

全部程序化生成，没有任何外部模型或贴图：地形、溪流、麦田、农舍、风车、树、篱笆、
云、鸟都是代码按种子算出来的，改 `seed` 就换一片山谷。

**规模**：约 121 万体素，37.5 万三角面，13.5 万四边形。浏览器里 60fps 无压力
（截图用的是 Chrome 软件渲染 SwiftShader，慢是截图环境的问题，不是场景的问题）。

### 管线

| 文件 | 干什么 |
| --- | --- |
| `js/noise.js` | 确定性哈希噪声 / fBm / 山脊噪声 |
| `js/voxel.js` | 体素容器（大世界用扁平数组，道具用稀疏 Map）与作图工具 |
| `js/mesher.js` | 体素 → BufferGeometry，逐面 AO、线性空间顶点色 |
| `js/world.js` | 地形高度场、溪流、麦田、小路、野花 |
| `js/props.js` | 风车、农舍、谷仓、小桥、树、篱笆、草垛、水井 |
| `js/sky.js` | 天空穹顶、远山剪影、体素云、飞鸟、太阳 |
| `js/main.js` | 光照、阴影、后处理、相机、动画 |

### 画面上的几层

1. **大气透视**：远处几何按距离融进暖雾色（`Fog` 150→560），这是把 232×232 的小世界
   撑出纵深感的主要手段。
2. **云影**：片元里用两层值噪声算出缓慢漂移的大片阴影，**只压直射光不动环境光**
   （注入 `lights_fragment_end` 之后改 `reflectedLight.directDiffuse`）。
3. **麦穗透光**：逆光时穗子会透光。按视线与「光的传播方向」的夹角算透射率，
   越靠近太阳方向越亮，这是黄昏麦田最要紧的一层。
4. **风**：顶点着色器按 `aWind.x` 做两组正弦叠加位移，底部不动、穗子摆幅最大。
5. **泛光**：只给真正 HDR 的东西（太阳本体、窗户、水面碎光）用，阈值 1.0、半径 0.2，
   半径给大了会把整片天空洗成灰白。

### 光

太阳固定在正北偏西 6.5°、仰角 12°（这两个数是拿 `tools/search.mjs` 反解出来的，
不是拍脑袋）。逆光构图，强度按物理量级给：`sun 7.6 / hemi 2.7 / fill 1.5`，
ACES 色调映射，曝光 1.0。

## 工具（改图时用）

出图前先算、再渲、再量。这套东西是为了在没有肉眼的情况下也能判断画面成立不成立。

```bash
node tools/check.mjs            # 不开浏览器跑一遍世界生成，打印体素规模与关键坐标地表高度
node tools/framing.mjs 0,1,2    # 把风车/农舍/桥/太阳投影到屏幕坐标，并检测地形遮挡
SUNEL=14 node tools/search.mjs  # 在机位参数空间里搜符合构图约束的解
./tools/shoot.sh hero "cam=0"   # 无头出图（软件渲染，约 1-2 分钟）
python3 tools/measure.py shots/hero.png    # 亮度分布/饱和度/天空色相/地标取样
./tools/shoot.sh id "cam=0&clay=1" && python3 tools/silhouette.py shots/id.png  # 白模剪影与遮挡
```

`measure.py` 会输出上/中/下三分之一的亮度与饱和度、直方图中间调占比、地平线位置、
地标区域的取样色。调光和调色基本都靠这几个数字：中间调占比低于 25% 说明直方图是
U 型（暗死黑 + 亮死白），暖色带 R−B 小于 0.05 说明黄昏味不够。

## 踩过的坑

- **AO 要跳过竖直面的「下侧邻居」**：屋瓦、山坡这类阶梯斜面，下一阶台阶正好在面正下方，
  经典 AO 会把整片坡面压暗一档。做法是法线 y=0 时不统计向下方向的遮挡。
- **顶点色必须在 linear 工作空间算**：hex 直写会被输出端二次提亮成粉彩。
- **自定义属性的 itemSize 必须对上**：这里每个顶点写了 3 个 float 却填 itemSize=1，
  着色器只读到前 1/3，而那一段全是地下土层——表现就是「风永远不动、透光完全没效果」，
  但画面看起来完全正常，不对比数值根本发现不了。
- **ACES 会把过亮的暖色洗成纯白**：太阳本体给 2.2 倍亮度时，天空和日轮都变成中性白。
  降亮度、收窄泛光半径，暖色才留得住。
- **相机机位要反解，不要目测**：`tools/framing.mjs` 里能算出「风车占画面 47%–70% 宽、
  帆顶离上边缘 6%、桥在 87% 高度且没被地形挡住」，这些比肉眼估得准。
- **无头出图别复用 Chrome 用户目录**，否则改完 JS 会读到磁盘缓存里的旧文件，
  排查时能白烧半小时。
